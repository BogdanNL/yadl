# yadl

Консольная утилита для скачивания файлов с Яндекс.Диска по публичной ссылке.
Работает на сервере без браузера и без графической подсистемы, авторизация и OAuth-токен не нужны.

## Сборка

```bash
cargo build --release
# бинарник: target/release/yadl
```

Требуется Rust 1.70+. Внешних зависимостей времени выполнения нет — получается один
исполняемый файл, который можно просто скопировать на сервер.

## Быстрый старт

```bash
yadl https://disk.yandex.ru/d/XXXXXXXXXXXXXX
```

Файл сохранится в текущий каталог под своим именем.

## Использование

```
yadl [OPTIONS] <URL>
```

| Опция | Описание |
|---|---|
| `<URL>` | Публичная ссылка: `https://disk.yandex.ru/d/...` или `https://yadi.sk/d/...` |
| `-o, --output <PATH>` | Куда сохранить. По умолчанию — имя файла из метаданных, недостающие каталоги создаются |
| `-p, --password <PASS>` | Пароль публичной ссылки. Можно передать через переменную `YADL_PASSWORD` |
| `--path <PATH>` | Путь внутри публичной папки, например `/subdir/file.bin`. Только `--backend cloud` |
| `--backend <cloud\|web>` | Способ получения прямой ссылки, по умолчанию `cloud` |
| `--resume` | Докачать существующий файл (HTTP `Range`) |
| `--info` | Показать метаданные и прямую ссылку, ничего не скачивая |
| `-h, --help` | Справка |

### Примеры

Посмотреть, что лежит по ссылке, не скачивая:

```bash
$ yadl "$URL" --info
name:   archive.tar.gz
type:   file
size:   1048576 bytes
md5:    cc6e56f1be4a3f4a0f951fe91ff19edc
sha256: c2f255ee14d10c4006c66302e1b761796dd739c69296e271ec9bb0dbbeeaaf56
via:    cloud-api
href:   https://downloader.disk.yandex.ru/disk/...
```

Ссылка с паролем:

```bash
yadl "$URL" -p 'секрет'
YADL_PASSWORD='секрет' yadl "$URL"   # пароль не попадёт в историю и в ps
```

Сохранить под своим именем в конкретный каталог:

```bash
yadl "$URL" -o /srv/data/dump.bin
```

Продолжить прерванную загрузку:

```bash
yadl "$URL" -o dump.bin --resume
```

Скачать один файл из публичной папки:

```bash
yadl "$URL" --path /logs/2026-08-14.tar.gz
```

Проверить целостность (утилита сверяет размер, хеш — на вашей стороне):

```bash
yadl "$URL" -o file.bin
yadl "$URL" --info | awk '/^md5:/ {print $2"  file.bin"}' | md5sum -c -
```

Использовать в скрипте прямую ссылку, а качать чем-то другим:

```bash
HREF=$(yadl "$URL" --info | sed -n 's/^href:   //p')
curl -L -o file.bin "$HREF"     # ссылка живёт несколько минут
```

## Два backend'а

**`cloud` (по умолчанию)** — публичный REST API `cloud-api.yandex.net`. Документированный
контракт, анонимный доступ, попутно отдаёт `md5`/`sha256`. Обычный рабочий режим.

**`web`** — повторяет ровно то, что делает кнопка «Скачать» на странице: читает `sk` и `hash`
из встроенного в HTML `store-prefetch`, затем `POST /public/api/download-url`, включая ретрай
на ответ `wrongSk`. Нужен как запасной путь, если публичный API начнёт отвечать 429/403:

```bash
yadl "$URL" --backend web
```

Оба пути приводят к одной и той же временной ссылке на `downloader.disk.yandex.ru`, которая
редиректит на storage-хост. Какой путь реально сработал, показывает строка `via:` в `--info`.

### Ссылки с паролем

Пароль умеет только web-путь: он делает `POST /public/api/check-password`, получает `passToken`
и передаёт его в `download-url`. У публичного REST API канала для пароля нет — на защищённой
ссылке он отвечает `403 DiskSymlinkPasswordRequiredError`, и никакого параметра для пароля
в его контракте не предусмотрено.

Поэтому `--backend cloud` с `--password` печатает в stderr

```
note: публичный REST API не принимает пароль, переключаюсь на web-путь
```

и прозрачно доводит загрузку до конца. Обе команды ниже равнозначны по результату:

```bash
yadl "$URL" -p 'секрет'                  # cloud → авто-переключение на web
yadl "$URL" --backend web -p 'секрет'    # web сразу
```

Без `--password` защищённая ссылка завершается ошибкой `ссылка защищена паролем — укажите --password`,
при неверном пароле — `неверный пароль`.

Для защищённых ссылок `md5`/`sha256` в `--info` не показываются: их отдаёт только cloud-api,
который к таким ссылкам доступа не имеет. Имя и размер берутся из прямой ссылки.

## Поведение и ограничения

* Прямая ссылка **временная** (порядка нескольких минут) — кэшировать её между запусками
  бесполезно, каждый запуск получает свежую.
* `--resume` полагается на `Accept-Ranges: bytes` у storage-хоста. Если сервер проигнорирует
  `Range` и ответит 200, утилита молча начнёт загрузку с нуля.
* `--resume` не проверяет, что уже скачанный кусок относится к тому же файлу. Не смешивайте
  разные ссылки в одном `-o`.
* Публичная папка без `--path` скачивается одним zip-архивом (к имени добавляется `.zip`).
  Этот сценарий описан контрактом API, но на реальной папочной ссылке не проверялся.
* Размер сверяется с метаданными; при расхождении — ненулевой код возврата и сообщение об ошибке.
* `--path` работает только с `--backend cloud`: во внутреннем web-API листинг папки устроен иначе.

## Диагностика

Все ошибки печатаются в stderr, код возврата ненулевой. Типичные случаи:

| Сообщение | Причина |
|---|---|
| `cloud-api вернул 404` | ссылка отозвана, опечатка или ресурс удалён |
| `ссылка защищена паролем — укажите --password` | на публикацию поставлен пароль |
| `неверный пароль` | `check-password` ответил 403/309 |
| `на странице нет store-prefetch` | (`--backend web`) ссылка невалидна |
| `download-url отказал` | не сохранились cookies — проверьте, что нет прокси, режущего `Set-Cookie` |
| `размер не совпал` | обрыв соединения; повторите с `--resume` |

## Сборка релиза под Windows

Workflow `.github/workflows/release-windows.yml` запускается вручную
(**Actions → Windows release → Run workflow**) и принимает:

| Ввод | Смысл |
|---|---|
| `version` | Версия, например `0.1.0`. Становится именем тега и попадает в имя архива |
| `branch` | Ветка для сборки. Пусто — та, что выбрана в выпадающем списке запуска |
| `overwrite_tag` | Перенести существующий тег на собранный коммит (по умолчанию нет) |

Что делает: собирает `cargo build --release --locked` на `windows-latest`, кладёт
`yadl.exe`, `README.md` и `LICENSE` в `yadl-windows-<version>.zip`, создаёт тег и релиз
с этим именем и заливает архив в релиз. Если релиз с такой версией уже есть, тег остаётся
на месте, а архив заменяется (`gh release upload --clobber`). Архив дополнительно
доступен как artifact самого запуска, а sha256 и размер печатаются в summary.

## Ресурсы

Публичный API Яндекс.Диска — то, на чём построен backend `cloud`:

* [REST API Диска — обзор и содержание](https://yandex.ru/dev/disk-api/doc/ru/) ([старый адрес](https://yandex.ru/dev/disk/rest/))
* [Операции над опубликованными файлами и папками](https://yandex.ru/dev/disk-api/doc/ru/reference/public) —
  описание `GET /v1/disk/public/resources` и `/v1/disk/public/resources/download`
  ([English](https://yandex.ru/dev/disk-api/doc/en/reference/public))
* [Объекты в ответах API](https://yandex.ru/dev/disk-api/doc/ru/reference/response-objects) — поля
  `Resource`, `ResourceList`, `Link`
* [Начало работы](https://yandex.ru/dev/disk-api/doc/ru/concepts/quickstart) — нужно, только если
  понадобится OAuth-доступ к приватным файлам; для публичных ссылок токен не требуется
* [Справка Яндекс.Диска](https://yandex.ru/support/disk/) — как публиковать файлы и ставить пароль
  на ссылку

Backend `web` использует внутренние эндпоинты `disk.yandex.ru/public/api/*`, которые не
документированы и могут измениться без предупреждения.

Полезное по механике загрузки:

* [RFC 9110, §14 Range Requests](https://www.rfc-editor.org/rfc/rfc9110.html#name-range-requests) —
  на чём основан `--resume`
* [reqwest](https://docs.rs/reqwest/latest/reqwest/) — HTTP-клиент, на котором написана утилита
* [Patchright](https://github.com/Kaliiiiiiiiii-Vinyzu/patchright) — использовался для снятия
  трафика браузера при разборе протокола
