# yadl

Консольная утилита для скачивания файлов с Яндекс.Диска по публичной ссылке.
Работает на сервере без браузера и без графической подсистемы, авторизация и OAuth-токен не нужны.

## Сборка

```bash
cargo build --release
# бинарник: target/release/yadl
```

Требуется Rust 1.70+. Внешних зависимостей времени выполнения нет — получается один
исполняемый файл, который можно просто скопировать на сервер.

## Быстрый старт

```bash
yadl https://disk.yandex.ru/d/XXXXXXXXXXXXXX
```

Файл сохранится в текущий каталог под своим именем.

## Использование

```
yadl [OPTIONS] <URL>
```

| Опция | Описание |
|---|---|
| `<URL>` | Публичная ссылка: `https://disk.yandex.ru/d/...` или `https://yadi.sk/d/...` |
| `-o, --output <PATH>` | Куда сохранить. По умолчанию — имя файла из метаданных, недостающие каталоги создаются |
| `--path <PATH>` | Путь внутри публичной папки, например `/subdir/file.bin` |
| `--backend <cloud\|web>` | Способ получения прямой ссылки, по умолчанию `cloud` |
| `--resume` | Докачать существующий файл (HTTP `Range`) |
| `--info` | Показать метаданные и прямую ссылку, ничего не скачивая |
| `-h, --help` | Справка |

### Примеры

Посмотреть, что лежит по ссылке, не скачивая:

```bash
$ yadl "$URL" --info
name:   archive.tar.gz
type:   file
size:   1048576 bytes
md5:    cc6e56f1be4a3f4a0f951fe91ff19edc
sha256: c2f255ee14d10c4006c66302e1b761796dd739c69296e271ec9bb0dbbeeaaf56
href:   https://downloader.disk.yandex.ru/disk/...
```

Сохранить под своим именем в конкретный каталог:

```bash
yadl "$URL" -o /srv/data/dump.bin
```

Продолжить прерванную загрузку:

```bash
yadl "$URL" -o dump.bin --resume
```

Скачать один файл из публичной папки:

```bash
yadl "$URL" --path /logs/2026-08-14.tar.gz
```

Проверить целостность (утилита сверяет размер, хеш — на вашей стороне):

```bash
yadl "$URL" -o file.bin
yadl "$URL" --info | awk '/^md5:/ {print $2"  file.bin"}' | md5sum -c -
```

Использовать в скрипте прямую ссылку, а качать чем-то другим:

```bash
HREF=$(yadl "$URL" --info | sed -n 's/^href:   //p')
curl -L -o file.bin "$HREF"     # ссылка живёт несколько минут
```

## Два backend'а

**`cloud` (по умолчанию)** — публичный REST API `cloud-api.yandex.net`. Документированный
контракт, анонимный доступ, попутно отдаёт `md5`/`sha256`. Обычный рабочий режим.

**`web`** — повторяет ровно то, что делает кнопка «Скачать» на странице: читает `sk` и `hash`
из встроенного в HTML `store-prefetch`, затем `POST /public/api/download-url`, включая ретрай
на ответ `wrongSk`. Нужен как запасной путь, если публичный API начнёт отвечать 429/403:

```bash
yadl "$URL" --backend web
```

Оба пути приводят к одной и той же временной ссылке на `downloader.disk.yandex.ru`, которая
редиректит на storage-хост.

## Поведение и ограничения

* Прямая ссылка **временная** (порядка нескольких минут) — кэшировать её между запусками
  бесполезно, каждый запуск получает свежую.
* `--resume` полагается на `Accept-Ranges: bytes` у storage-хоста. Если сервер проигнорирует
  `Range` и ответит 200, утилита молча начнёт загрузку с нуля.
* `--resume` не проверяет, что уже скачанный кусок относится к тому же файлу. Не смешивайте
  разные ссылки в одном `-o`.
* Публичная папка без `--path` скачивается одним zip-архивом (к имени добавляется `.zip`).
  Этот сценарий описан контрактом API, но на реальной папочной ссылке не проверялся.
* Ссылки, защищённые паролем, не поддерживаются.
* Размер сверяется с метаданными; при расхождении — ненулевой код возврата и сообщение об ошибке.

## Диагностика

Все ошибки печатаются в stderr, код возврата ненулевой. Типичные случаи:

| Сообщение | Причина |
|---|---|
| `cloud-api вернул 404` | ссылка отозвана, опечатка или ресурс удалён |
| `на странице нет store-prefetch` | (`--backend web`) ссылка невалидна либо требует пароль |
| `download-url отказал (wrongSk=true)` | не сохранились cookies — проверьте, что нет прокси, режущего `Set-Cookie` |
| `размер не совпал` | обрыв соединения; повторите с `--resume` |
